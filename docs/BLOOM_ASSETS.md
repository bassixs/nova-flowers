# ТЗ: покадровая последовательность раскрытия цветка

Сейчас hero-сцена работает на **процедурном 3D-пионе** (`src/bloom/peony.ts`) — это временная замена.
Для фотографического результата нужна последовательность кадров. Компонент уже готов её принять
(`src/bloom/sequence.ts`), достаточно положить кадры и переключить режим.

## Что снять / сгенерировать

| Параметр | Требование |
|---|---|
| Цветок | Пион (Sarah Bernhardt или Coral Charm) либо садовая роза (David Austin) |
| Начало (кадр 0) | Плотный круглый бутон с 4–5 зелёными чашелистиками, лепестки сомкнуты |
| Конец (последний кадр) | Полностью раскрытый пышный цветок, внешние лепестки опущены почти горизонтально, центр — плотная «шапка» внутренних лепестков |
| Движение | Непрерывное: сначала расходятся внешние лепестки (кончики отгибаются наружу), затем средние, в конце слегка раскрываются внутренние. Без скачков и пропусков |
| Ракурс | Камера ~15° над горизонтом в начале → ~50° сверху в конце (плавный облёт допускается), цветок по центру кадра или на 60% ширины |
| Свет | Мягкий рассеянный, ключевой источник сверху-слева, тёплый (4500–5000 K). Без жёстких бликов |
| Фон | Однородный тёплый молочный `#F2EBE2` → чуть темнее по краям (виньетка). Без предметов. Фон одинаковый на всех кадрах |
| Стебель | Виден в начале, уходит за нижний край к концу |
| Глубина резкости | Цветок целиком в фокусе |

Источник: time-lapse съёмка (6–10 ч, интервал 30–60 с) с последующей стабилизацией и
цветокоррекцией, 3D-рендер (Houdini / Blender, симуляция раскрытия) или генеративное видео
с жёстким контролем непрерывности. Ключевое требование — кадры **визуально согласованы**:
одинаковые фон, экспозиция, баланс белого, положение цветка.

## Технические параметры

- Количество: 90–150 кадров (по умолчанию в конфиге 120).
- Разрешение: 1920×1080 (16:9) — для десктопа; опционально отдельная серия 1080×1920 для мобильных.
- Формат: WebP, качество 70–78, ~60–120 КБ на кадр. Итоговый объём серии ≤ 10–12 МБ.
- Имена: `public/bloom/frame_0000.webp … frame_0119.webp`.
- Важное содержимое — в центральной безопасной зоне 60% (кадр масштабируется по принципу cover).

## Подключение

```ts
// src/config/content.ts
export const bloom = {
  mode: 'sequence',
  sequence: { path: 'bloom/frame_{i}.webp', frames: 120, pad: 4, critical: 12 },
  scrollLength: 3.2,
};
```

Загрузка: сначала первый кадр, затем 12 «критических» равномерно по шкале (сцена сразу
работает грубо), затем остальные пачками по 6. При отрисовке берётся ближайший загруженный
кадр — пустого экрана не бывает даже на медленном интернете.
