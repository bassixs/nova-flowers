# FLEURÉ — демо-сайт премиального цветочного салона

Демонстрационный лендинг-магазин с кинематографичным раскрытием пиона при прокрутке.
React + Vite + TypeScript + GSAP ScrollTrigger + Canvas. Публикация — GitHub Pages.

**Сайт:** https://bassixs.github.io/nova-flowers/

> Это демо: контакты, цены, условия доставки и отзывы — пример наполнения. Заказы не отправляются.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173/nova-flowers/
npm run build      # сборка в dist/
npm run preview    # просмотр production-сборки
```

`bloom-preview.html` (только в dev: `/nova-flowers/bloom-preview.html?p=0,0.3,0.6,1`) —
стенд для настройки процедурного цветка по кадрам.

## Публикация на GitHub Pages

Уже настроено: `.github/workflows/deploy.yml` собирает проект и публикует его при каждом push в `main`.

1. Settings → Pages → Build and deployment → Source: **GitHub Actions** (включено).
2. `git push` в `main` → вкладка Actions → «Deploy to GitHub Pages» → через 1–2 минуты сайт обновится.
3. Base path задан в `vite.config.ts` (`/nova-flowers/`). Для собственного домена соберите с
   `VITE_BASE=/` и добавьте `public/CNAME`.

## Раскрытие цветка — как устроено

- Секция hero **закрепляется** (`ScrollTrigger pin`) на 3.2 высоты экрана; прогресс прокрутки 0…1
  передаётся в Canvas-рендерер с инерционным сглаживанием. Работает в обе стороны: при прокрутке
  вверх цветок закрывается.
- **Процедурный пион** (`src/bloom/peony.ts`) — не CSS-трансформация фото. около 80 лепестков в 8 слоях плюс чашелистики;
  каждый лепесток — изогнутая 3D-поверхность: «позвоночник» с изгибом, ширина, чашевидность,
  волнистая кромка. В бутоне лепестки лежат на сфере (обёрнуты вокруг оси), при раскрытии
  кончики разворачиваются наружу, слои стартуют с задержкой от внешних к внутренним.
  Перспективная проекция, сортировка по глубине, освещение по нормали, падающие тени,
  окклюзия у основания, прожилки, лёгкое «дыхание» лепестков в покое.
- Таймлайн: 0–20% — бутон, едва заметное движение и смена света; 20–45% — внешние лепестки,
  отъезд камеры и наклон сверху; 45–75% — пышное раскрытие + построчно проявляется заголовок
  (маска + blur→sharp); 75–100% — финальная композиция, подзаголовок и кнопки.
- Производительность: DPR ограничен (1.6 / 2 на мобильных), перерисовка только при изменении
  прогресса либо ~30 fps для «дыхания», рендер останавливается, когда hero вне экрана.
- Фолбэки: `prefers-reduced-motion` — без pin, статичный раскрытый цветок и весь текст;
  нет Canvas или ошибка ассетов — фото-постер с текстом. Пустого экрана не бывает.
- Переход на фотографическую покадровую версию — см. **docs/BLOOM_ASSETS.md**.

## Реализованные анимации

- Hero: раскрытие цветка, смена света фона, облёт камеры, уход вступительной фразы, построчный
  заголовок с blur→sharp, появление подзаголовка и кнопок, индикатор прокрутки.
- Заголовки секций: построчное раскрытие из-под маски + blur→sharp (по словам, без анимации букв).
- Изображения: reveal clipping-маской с масштабированием, параллакс (философия, доставка).
- Карточки: zoom фото, сдвиг названия, появление «Подробнее», раскрывающаяся кнопка «В корзину»,
  плавная перестройка при фильтрации.
- Поводы: горизонтальная галерея при вертикальной прокрутке (desktop), свайп со snap (mobile).
- Мастерская: sticky-кадр со сменой фото clip-маской синхронно с шагами.
- Отзывы: слайдер со сменой направления; финал: раскрытие фото из «окна» на весь экран.
- Микро: заливка кнопок, подчёркивания ссылок, бургер→крестик, меню-шторка со stagger,
  «пульс» счётчика корзины, модалки/ящик с анимацией входа/выхода, тосты, галочка успеха.

## Функциональность

Адаптивная навигация и мобильное меню, якорные переходы, фильтр каталога + фильтр по поводу,
карточка букета (размеры S/M/L, количество), корзина в localStorage, оформление с валидацией
и маской телефона, демо-подтверждение, Esc/клик по фону/focus trap/возврат фокуса, тосты,
skip-link, семантическая разметка, мета-теги и schema.org.

## Интеграция заказов

`src/services/orders.ts`: интерфейс `OrderAdapter`. Сейчас активен `demoAdapter` (ничего не
отправляет). Для Telegram / MAX / CRM реализуйте адаптер, который шлёт заказ на **ваш**
сервер или serverless-функцию — токены ботов и CRM нельзя хранить в статическом фронтенде.

|---|---|

| Отправка заказов | `src/services/orders.ts` |

## Ограничения и недостающие ассеты

- Нет фотографической покадровой съёмки раскрытия — используется процедурный пион
  (стилизованный, «фарфоровый», а не фотореалистичный). ТЗ на кадры: docs/BLOOM_ASSETS.md.
- Фото — Unsplash (лицензия допускает коммерческое использование); для реального клиента лучше
  собственная съёмка его букетов. Список источников: docs/CREDITS.md.
- Нет бэкенда, оплаты и админки каталога — каталог редактируется в конфиге.
